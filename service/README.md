# Информационно-аналитический сервис мониторинга природных пожаров

Команда LitWin · КосмоХакатон 2026 · кейс «Мониторинг природных пожаров».

Сервис принимает **пространственно-временной запрос** (полигон или прямоугольник + интервал дат) и возвращает:

* **термоточки** — пиксели активного горения VIIRS 375 м (точки, атрибуты FIRMS-подобные);
* **контуры гарей** и **зоны степени поражения** (слабая / средняя / сильная) по Sentinel-2 20 м;
* **аналитическую справку**: общая площадь гарей в гектарах, распределение по трём классам степени, таблица контуров, термоточки по датам, типы покрова, сравнение модели с эталоном.

Всё доступно и в веб-интерфейсе (карта + справка + выгрузки), и через **REST API** без интерфейса (`/docs` — Swagger).

Работает на заранее подготовленном наборе сцен — обучающей выборке с геопривязкой (у тестовых чипов привязка и даты удалены). Каталог (`service/data/catalog`, ~24 МБ) лежит в репозитории, скачивать данные не нужно.

## Быстрый старт

Из **корня репозитория**, Python 3.12 (нужен для зафиксированной версии NumPy):

```bash
python3 -m venv service/.venv
service/.venv/bin/pip install -r service/requirements.txt
service/.venv/bin/uvicorn service.app.main:app --host 0.0.0.0 --port 8000
```

* веб-интерфейс: <http://localhost:8000/>
* документация API (Swagger UI): <http://localhost:8000/docs>, ReDoc: <http://localhost:8000/redoc>
* проверка: `curl http://localhost:8000/api/health`

Каталог загружается при старте (~1 с), весь запрос по каталогу отрабатывает за 0,3–0,6 с.

### Docker

```bash
docker compose -f service/docker-compose.yml up --build      # из корня репозитория

docker build -f service/Dockerfile -t firemon-service . && docker run --rm -p 8000:8000 firemon-service
```

## Веб-интерфейс

* **Территория**: весь каталог · граница AOI · прямоугольник (протянуть мышью по карте или ввести bbox) · полигон (щелчки по карте, двойной щелчок — завершить, `Backspace` — убрать вершину, `Esc` — отмена) · загрузка GeoJSON-файла.
* **Период**: даты начала и конца; **лента времени** внизу карты — помесячно термоточки (вверх) и площадь гарей (вниз); выбор периода протягиванием мышью, щелчок по году — год (или сезон апр–окт).
* **Источник**: «Модель» (результаты нашей модели) или «Эталон» (разметка организаторов) — переключатель в шапке.
* **Карта**: термоточки (день/ночь), контуры гарей (цвет — преобладающая степень), попиксельный растр степени 20 м при крупном масштабе, покрытие снимками, граница AOI; всё вне полигона запроса притемняется. Слои включаются и выключаются в панели «Слои».
* **Подложка**: «Тёмная» (по умолчанию) и «Светлая» — векторные тайлы OpenFreeMap (данные OpenStreetMap) в собственном стиле: вода, застройка, дороги, подписи населённых пунктов по-русски, без государственных границ и подписей стран; «Спутник» — Esri World Imagery без слоя границ.
* **Карточка контура** (щелчок по гари на карте или в таблице): площади по классам, даты снимков, превью Sentinel-2 до/после пожара (SWIR2-NIR-Red: B12, B8A, B4), наложенное по реальным углам чипа.
* **Справка**: площадь гарей, число контуров и термоточек, распределение по степени, сравнение «модель — эталон» (IoU, F1, точность степени, F1 термоточек), график термоточек, типы покрова, сортируемая таблица контуров, методика и готовая команда `curl` для того же запроса.
* **Выгрузка** (по текущему запросу, включая нарисованный полигон): контуры — GeoJSON / Shapefile / CSV, зоны степени — GeoJSON / Shapefile, термоточки — GeoJSON / Shapefile / CSV, справка — JSON / CSV / ZIP.

## REST API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | состояние сервиса |
| GET | `/api/v1/meta` | охват, период, источники, классы, помесячные ряды |
| GET / POST | `/api/v1/query` | главный запрос: термоточки + контуры + зоны + справка |
| GET / POST | `/api/v1/hotspots` | термоточки: `format=geojson\|csv\|shp\|gpkg` |
| GET / POST | `/api/v1/burn-scars` | контуры (`layer=scars`) или зоны степени (`layer=zones`): `format=geojson\|shp\|gpkg\|csv`, `crs=4326\|utm`, `detail=exact\|display`, `clip=true\|false` |
| GET / POST | `/api/v1/report` | справка: `format=json\|csv\|severity_csv\|scars_csv\|landcover_csv\|hotspots_csv\|zip`, `compare=true\|false` |
| GET | `/api/v1/scars/{scar_id}` | карточка контура: атрибуты, покров, углы чипа, превью |
| GET | `/api/v1/aoi` | граница территории мониторинга (GeoJSON) |
| GET | `/api/v1/chips?kind=bs\|af` | покрытие: чипы Sentinel-2 / тайлы VIIRS |
| POST | `/api/v1/analyze/bs`, `/api/v1/analyze/af` | необязательно: обработка нового чипа (GeoTIFF) |

**Параметры запроса.** GET: `bbox=minLon,minLat,maxLon,maxLat` **или** `geometry=<GeoJSON/WKT>`, `date_from`, `date_to` (`YYYY-MM-DD`, включительно), `source=model|reference`. POST: то же в JSON-теле; `geometry` — GeoJSON Polygon/MultiPolygon, Feature или FeatureCollection в EPSG:4326. Без `bbox`/`geometry` — весь каталог; без дат — весь период; без `source` — модель (если есть в каталоге).

Ошибки параметров — HTTP 422 с понятным сообщением в поле `message` (дата начала позже конца, неверный bbox, самопересекающийся полигон, не-полигон, координаты вне EPSG:4326, `geometry` и `bbox` одновременно).

### Примеры

```bash
# главный запрос по прямоугольнику за 2021 год — всё сразу, без интерфейса
curl "http://localhost:8000/api/v1/query?bbox=43,47,46,50&date_from=2021-01-01&date_to=2021-12-31"

# справка по прямоугольнику за 2021 год (JSON)
curl "http://localhost:8000/api/v1/report?bbox=43,47,46,50&date_from=2021-01-01&date_to=2021-12-31"

# то же — сводка CSV и пакет ZIP (JSON + все таблицы CSV)
curl -OJ "http://localhost:8000/api/v1/report?bbox=43,47,46,50&date_from=2021-01-01&date_to=2021-12-31&format=csv"
curl -OJ "http://localhost:8000/api/v1/report?bbox=43,47,46,50&format=zip"

# полный запрос по полигону (термоточки, контуры, зоны, справка)
curl -X POST http://localhost:8000/api/v1/query -H 'Content-Type: application/json' -d '{
  "geometry": {"type": "Polygon", "coordinates": [[[44,48],[45.5,48],[45.5,49.2],[44,49.2],[44,48]]]},
  "date_from": "2021-04-01", "date_to": "2021-10-31", "source": "reference"}'

# контуры гарей по полигону в Shapefile (zip) и зоны степени в GeoJSON
curl -OJ -X POST "http://localhost:8000/api/v1/burn-scars?format=shp" -H 'Content-Type: application/json' \
     -d '{"geometry": {"type":"Polygon","coordinates":[[[44,48],[45.5,48],[45.5,49.2],[44,49.2],[44,48]]]}}'
curl -OJ "http://localhost:8000/api/v1/burn-scars?layer=zones&bbox=43,47,46,50"

# термоточки CSV за сезон 2020
curl -OJ "http://localhost:8000/api/v1/hotspots?date_from=2020-04-01&date_to=2020-10-31&format=csv"
```

## Методика

**Термоточки.** Каждый пиксель маски активного горения (модель или эталон) → точка в центре пикселя VIIRS I-диапазона (375 м), пересчёт UTM → WGS84 (pyproj). Атрибуты: `hotspot_id`, `acq_datetime` (UTC), `acq_date`, `acq_time`, `satellite`, `daynight` (D, если зенитный угол Солнца < 85°), `bright_ti4`, `bright_ti5` (яркостные температуры I4/I5, K), `delta_t`, `confidence` (вероятность модели; для эталона 1), `landcover` (ESA WorldCover), углы Солнца/сенсора, `chip_id`, `utm_epsg`, `source`. FRP не вычисляется: для I4 VIIRS нет надёжно проверенного коэффициента метода MIR-радиации, а приводить непроверенную величину мы не стали.

**Контуры гарей.** Связная область пикселей со степенью ≥ 1 (8-связность) в маске 20 м. Полигоны строятся попиксельно (`rasterio.features.shapes`, 4-связность, затем группировка по 8-связной метке в MultiPolygon) — геометрия всегда валидна, а её площадь ровно равна числу пикселей × 400 м². **Зоны степени** — пиксели одного класса внутри контура (≤ 3 зоны на контур). Мелкие компоненты не удаляются: площади в справке совпадают с растром до пикселя. Идентификаторы стабильны: `<chip_id>-R###` (эталон) / `<chip_id>-M###` (модель), номера — по убыванию площади; зона — `<scar_id>-Z<степень>`.

**Площади.** Растры Sentinel-2 заданы на сетке UTM (EPSG:32637 / 32638) с пикселем 20 × 20 м, поэтому площадь без обрезки = число пикселей × 0,04 га — ровно так же посчитан `burn_area_ha` в `meta.csv` (проверяется при сборке каталога и в тестах: сумма по каталогу 236 360,04 га = сумме `burn_area_ha`). Если полигон запроса пересекает контур, точная попиксельная геометрия контура и его зон пересекается с полигоном запроса, перепроецированным в ту же зону UTM (стороны полигона предварительно уплотняются до ~1 км, чтобы прямые в WGS84 правильно легли в UTM), и площадь пересечения считается планиметрически в UTM. Все площади ведутся в целых сотых гектара, поэтому суммы по классам, по контурам и итог сходятся без ошибок округления; доли по классам в сумме дают ровно 100 %.

**Фильтр по времени.** Термоточки — дата съёмки (UTC) в `[date_from, date_to]` включительно. Гарь попадает в выборку, если её окно наблюдения пересекается с периодом: `date_pre ≤ date_to` и `date_post ≥ date_from`.

**Фильтр по пространству.** Термоточки — точка внутри полигона (граница включается). Гари — пересечение с полигоном; при `clip=true` (по умолчанию) и геометрия, и площади обрезаются полигоном, атрибут `clipped=1` отмечает такие контуры, `area_total_ha` — полная площадь контура.

**Типы покрова** (ESA WorldCover) в справке: для необрезанных контуров — точно по пикселям; для обрезанных площадь каждой зоны распределяется по типам покрова пропорционально числу пикселей (в справке помечено).

**Сравнение с эталоном** (когда в каталоге есть оба источника): площади по классам для каждого источника — тем же способом, что и в справке; попиксельные IoU / точность / полнота / F1 гарей, IoU по каждому классу, точность степени на пикселях, горевших по обоим источникам, и матрица ошибок 4 × 4 (пиксель учитывается, если его центр внутри полигона запроса); для термоточек — совпадение пикселя VIIRS (сцена, строка, столбец).

## Форматы выгрузки

* **GeoJSON** — RFC 7946, WGS84 (EPSG:4326), явный член `crs` = `urn:ogc:def:crs:OGC:1.3:CRS84`, внешние кольца против часовой стрелки. Геометрия гарей по умолчанию точная (попиксельная), `detail=display` — упрощённая (допуск 20 м).
* **ESRI Shapefile** — zip: `.shp .shx .dbf .prj .cpg`, атрибуты в UTF-8 (`.cpg`), имена полей ≤ 10 символов (соответствие полей — в `README.txt` внутри архива). По умолчанию WGS84 (`.prj` — GCS_WGS_1984), площади при этом посчитаны в UTM. `crs=utm` — отдельный слой на каждую зону UTM в её проекции: площадь полигона в ГИС совпадает с атрибутом `area_ha`.
* **GeoPackage** — оба слоя (`burn_scars`, `severity_zones`) в одном файле, WGS84 или (`crs=utm`) по слою на зону UTM; пишется напрямую через SQLite, читается QGIS/GDAL.
* **CSV** — RFC 4180, разделитель «,», десятичная точка, UTF-8 с BOM (корректная кириллица в Excel).

Атрибуты контуров гарей (`burn_scars`; в скобках — имя поля DBF): `scar_id`, `chip_id`, `fire_event_id` (event_id), `date_pre`, `date_post`, `area_ha`, `area_low_ha` (area_low), `area_moderate_ha` (area_mod), `area_high_ha` (area_high), `share_low_pct` / `share_moderate_pct` / `share_high_pct` (shr_*), `dominant_severity` (dom_sev, 1–3), `dominant_label` (dom_label), `clipped`, `area_total_ha` (area_full), `n_pixels`, `pixel_size_m`, `utm_epsg`, `center_lon`, `center_lat`, `confidence` (средняя вероятность модели), `source`.

Атрибуты зон степени (`severity_zones`): `zone_id`, `scar_id`, `severity` (1–3), `severity_label` (слабая / средняя / сильная), `area_ha`, `share_of_scar_pct`, `n_pixels`, `chip_id`, `fire_event_id`, `date_pre`, `date_post`, `clipped`, `utm_epsg`, `source`.

Справка: `report.json` (полная), `report_summary.csv` (`section,metric,value,unit`), `report_severity.csv` (по классам + строка `total`), `report_scars.csv` (по контурам), `report_landcover.csv`, `report_hotspots_by_date.csv`; `format=zip` — всё вместе.

## Сборка каталога

Каталог собирается один раз из обучающей выборки (`train/af`, `train/bs` с `meta.csv`) и, при наличии, предсказаний модели:

```bash
pip install -r service/requirements-build.txt
python service/build_catalog.py --data-dir <путь>/train --pred-dir <путь к предсказаниям> --out service/data
```

`--pred-dir` необязателен — без него в каталоге только эталонная разметка.

**Каталог в репозитории собран на честных прогнозах финальной модели:** out-of-fold. Каждый чип train предсказан моделями, которые его не видели при обучении. Поэтому блок «Модель и эталон» в справке показывает реальное качество (IoU гарей ≈0.76, точность степени 0.99, F1 термоточек 0.96). Воспроизведение:

```bash
python scripts/export_oof_preds.py --data-dir <train> \
    --bs-runs runs/cv/gbdt_s1 runs/cv/ctx2_s2 runs/cv/unetpp_ctx_s2 runs/cv/rgy16_s42 runs/cv/rgy16_s7 runs/cv/rgy32 \
    --bs-weights 1 0.5 0.5 1 1 1 --bs-threshold 0.475 --bs-severity-mode class_median --bs-min-area 25 --af-oof runs/af_oof --out runs/service_preds
python service/build_catalog.py --data-dir <train> --pred-dir runs/service_preds --out service/data
```
(OOF-каталоги создаёт `python train.py --data-dir <train> --cv`.)

Формат предсказаний:

```
<pred_dir>/af/<chip_id>.npz   mask uint8 (H, W) 0/1,  prob float16 (H, W) — вероятность горения
<pred_dir>/bs/<chip_id>.npz   mask uint8 (H, W) 0..3, prob float16 (H, W) — вероятность гари
```

Сборщик (≈10 с на 12 ядрах) векторизует маски, считает атрибуты, строит превью Sentinel-2 и растры степени, проверяет валидность геометрии и совпадение площадей/числа пикселей с `meta.csv`, пишет всё в `service/data/catalog` (заменяется целиком). Параметры: `--workers`, `--no-quicklooks`, `--limit N` (отладка), `--aoi`.

Структура каталога: `meta.json` (сборка, проверки), `chips.json` (чипы S2 и сцены VIIRS с углами и датами), `<источник>/hotspots.json`, `<источник>/scars.json` (атрибуты), `<источник>/geometry.npz` (точная и упрощённая геометрия: целочисленные узлы пиксельной сетки, дельта-кодирование — без потерь), `<источник>/masks.npz` (маски для попиксельного сравнения), `<источник>/overlays/*.png` (растр степени), `quicklooks/*.jpg`.

Для отладки без модели: `python service/tools/make_fake_preds.py --data-dir <train> --out <dir>` — синтетические «предсказания» (искажённый эталон) в том же формате.

## Необязательно: анализ нового чипа

`POST /api/v1/analyze/bs` (multipart): `s2_pre`, `s2_post` (GeoTIFF B2 B3 B4 B5 B6 B7 B8A B11 B12 SCL), необязательно `s1_pre`, `s1_post`, `aux` → модель `firemon.bs.predict.predict_bs_chip` → контуры, зоны и площади (та же векторизация, что в каталоге; привязка из GeoTIFF). Вместо снимков можно передать готовую маску степени `mask` — тогда выполняется только векторизация и расчёт площадей. `POST /api/v1/analyze/af`: `viirs`, `aux` → термоточки. Нужны `rasterio`, `scipy` (`requirements-build.txt`) и зависимости модели (`torch`, веса); без них эндпоинты отвечают **503** с объяснением — остальной сервис работает.

## Ограничения

* Сервис работает на подготовленном наборе сцен (обучающая выборка с геопривязкой): 224 чипа Sentinel-2 (гари) и 420 сцен VIIRS (70 тайлов 96 × 96 км, 2019–2024). Вне их покрытия данных нет.
* Термоточки — пиксели 375 м, а не субпиксельные очаги; FRP не рассчитывается.
* Периоды гарей задаются парой снимков до/после, точная дата горения внутри окна неизвестна.
